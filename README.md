# Customer Shopping Behavior Analysis

An end-to-end data analytics project that explores customer purchasing patterns, product preferences, discounts, shipping choices, customer segments, and subscription behavior. The project uses **Python, PostgreSQL, SQL, and Power BI** to transform raw shopping data into business insights and recommendations.

## Project Overview

This project analyzes **3,900 customer purchase records** across multiple product categories. The objective is to understand how customer attributes and shopping behavior relate to revenue, product ratings, discounts, shipping, and subscriptions.

The workflow covers:
1. Data exploration and cleaning using Python.
2. Feature engineering and preparation of the dataset.
3. Loading the cleaned data into PostgreSQL.
4. Answering business questions using SQL.
5. Presenting key metrics and trends in an interactive Power BI dashboard.

## Dataset

- **Records:** 3,900
- **Original columns:** 18
- **Missing values:** 37 in `Review Rating`
- **Data file:** `customer_shopping_behavior.csv`

The dataset includes:

| Area | Example fields |

| Customer behavior | Previous Purchases, Frequency of Purchases, Discount Applied, Promo Code Used |

## Project Workflow

### 1. Data loading and exploration

The CSV file is loaded into Pandas. Initial inspection uses:
- `head()` to preview records
- `info()` to inspect columns and data types
- `describe()` to review summary statistics
- `isnull().sum()` to identify missing values

### 2. Data cleaning and preparation

The notebook performs the following steps:

- Imputes missing `Review Rating` values using the **median rating within each product category**.
- Converts column names to lowercase `snake_case`.
- Renames `purchase_amount_(usd)` to `purchase_amount`.
- Creates an `age_group` feature using age-based quantile bins.
- Creates `purchase_frequency_days` by mapping purchase-frequency labels to approximate day intervals.
- Checks whether `discount_applied` and `promo_code_used` contain the same information, then removes `promo_code_used` as a redundant field.

### 3. PostgreSQL integration

The prepared Pandas DataFrame is loaded into a PostgreSQL table named `customer` in a database named `customer_behavior`.

The notebook uses SQLAlchemy with the `psycopg2` driver to connect to PostgreSQL.

### 4. SQL business analysis

The SQL script contains queries for these ten business questions:

1. **Revenue by gender** – compares total purchase revenue generated by male and female customers.
2. **High-spending discount users** – finds customers who used a discount and spent at least the average purchase amount.
3. **Top five products by rating** – ranks products by average review rating.
4. **Shipping comparison** – compares average purchase amounts for Standard and Express shipping.
5. **Subscribers vs. non-subscribers** – compares customer count, average spend, and total revenue by subscription status.
6. **Discount-dependent products** – identifies products with the highest percentage of purchases where a discount was applied.
7. **Customer segmentation** – groups customers into New, Returning, and Loyal segments using previous purchase history.
8. **Top three products per category** – uses a window function to rank the most purchased products in each category.
9. **Repeat buyers and subscriptions** – checks subscription status among customers with more than five previous purchases.
10. **Revenue by age group** – calculates revenue contribution by age group.

### 5. Power BI dashboard

The Power BI report provides an interactive view of customer behavior. It includes KPI cards and visual breakdowns for subscription status, revenue and sales by category, and revenue and sales by age group. Slicers allow users to explore the data by customer and shopping attributes.

Open `customer_behavior_dashboard.pbix` with Power BI Desktop to interact with the report.

## Business Recommendations

Based on the analysis, the project proposes the following actions:

1. **Boost subscriptions:** Promote exclusive benefits to encourage more customers to subscribe.
2. **Build customer loyalty:** Reward repeat buyers and encourage more customers to become loyal customers.
3. **Review discount policies:** Evaluate discount-dependent products and balance promotions with margin control.
4. **Improve product positioning:** Highlight highly rated and best-selling products in campaigns.
5. **Use targeted marketing:** Focus campaigns on high-revenue age groups and customers interested in express shipping.

## How to Run the Project

### Prerequisites

Install or have access to:

- Python 3
- Jupyter Notebook or Google Colab
- PostgreSQL and pgAdmin (or another PostgreSQL client)
- Power BI Desktop

### Step 1: Clone the repository

```bash
git clone <your-github-repository-url>
cd Customer-Shopping-Behavior-Analysis
```

### Step 2: Install Python dependencies

```bash
pip install pandas sqlalchemy psycopg2-binary jupyter
```

### Step 3: Run the notebook

Open `customer_shopping_behavior.ipynb` in Jupyter Notebook or upload it to Google Colab.

Make sure `customer_shopping_behavior.csv` is in the expected location. If you are running locally, update the CSV path in the first notebook cell as needed.

### Step 4: Configure PostgreSQL

1. Start PostgreSQL and create a database named `customer_behavior`.
2. Open the notebook's PostgreSQL connection cell.
3. Replace the username, password, host, port, and database values with your own PostgreSQL connection details.
4. Run the notebook cells to prepare the data and load the DataFrame into the `customer` table.

**Security note:** Do not commit database passwords, connection strings containing credentials, or other secrets to GitHub. Use environment variables or a local configuration file excluded through `.gitignore`.

### Step 5: Run the SQL analysis

Open `customer_behavior.sql` in pgAdmin or another PostgreSQL SQL client, connect to the database containing the `customer` table, and execute the queries.

### Step 6: Open the Power BI dashboard

Open `customer_behavior_dashboard.pbix` in Power BI Desktop. If Power BI requests a data source, update it to point to your local data source.
